# NITEOS Hunt V5: бесплатные источники кадастра, владельцев и ЛПР

Дата анализа: 2026-09-14.

## Что хотели получить

Пользовательский сценарий:

1. Вводим город/регион и тип здания.
2. Система находит конкретное коммерческое здание, пригодное для архитектурной подсветки.
3. По зданию подтверждается кадастр: кадастровый номер, адрес, площадь, источник.
4. По кадастру/публичным документам определяется реальный правообладатель или балансодержатель.
5. Если владелец - юрлицо, подтверждаем компанию по ИНН/ОГРН.
6. Выходим на ЛПР: собственник/бенефициар, гендиректор, технический директор, главный инженер, главный энергетик, эксплуатация объекта.
7. Контакты показываем только если они найдены в открытом источнике и привязаны к конкретному человеку или роли.

## Что сейчас есть в коде

Текущий V5 уже умеет:

- искать объект по картам: 2GIS, Yandex/HTML, Nominatim;
- получать фото, если его вернул источник или visual layer;
- пытаться получить кадастр через `pynspd`;
- искать кадастровый номер в web-страницах по regex;
- подтверждать компанию через DaData по ИНН;
- искать людей и контакты через открытый web-search;
- не выдумывать контакты, если прямого публичного подтверждения нет.

Проблема:

- НСПД не является источником владельца/ЛПР.
- Поиск по картам почти никогда не дает правообладателя.
- `FreeCadastreWebProvider` сейчас ищет страницы точечно, но не имеет собственной базы публичных лотов/документов.
- `known_public_sources.py` - временный seed, а не полноценный парсер.
- Нет отдельной таблицы evidence/source trail: из какого документа пришел кадастр, собственник, ИНН, роль человека, контакт.

## Бесплатные источники кадастра

### 1. НСПД / Росреестр

Источник: `https://nspd.rosreestr.gov.ru/`.

Что можно получать:

- кадастровый номер;
- геометрию/координаты;
- адрес;
- площадь;
- кадастровую стоимость, если поле доступно;
- тип объекта: участок, здание, сооружение, ОНС.

Что нельзя гарантированно получать:

- ФИО собственника;
- ИНН собственника;
- персональные контакты;
- ЛПР.

Роль в системе:

- основной бесплатный источник подтверждения кадастрового объекта;
- используется для проверки, что найденное на карте здание действительно имеет кадастровый объект;
- не должен считаться источником владельца.

Что нужно доработать:

- сделать отдельный `NspdOfficialProvider`;
- искать сначала ОКС/здания по координатам, потом участок;
- если найден участок, подтягивать связанные ОКС;
- сохранять все кандидаты, а не только первый;
- ранжировать по расстоянию, адресу и типу объекта.

### 2. ГИС Торги / torgi.gov.ru

Источник: `https://torgi.gov.ru/`.

Что можно получать:

- карточки лотов недвижимости;
- кадастровые номера;
- адрес;
- площадь;
- фото и документы;
- организатора/продавца/собственника/балансодержателя;
- ИНН/ОГРН организатора или собственника, если указан;
- ссылки на документы, где часто лежат выписки ЕГРН, приложения, извещения.

Роль в системе:

- лучший бесплатный источник связки `здание -> кадастр -> собственник/продавец`;
- надо парсить не только HTML, а открытые данные/JSON/XML и документы.

Что нужно доработать:

- сделать `TorgiGovProvider`;
- ingest открытых данных/лот-карточек;
- фильтр по региону/городу/категории недвижимости;
- извлечение кадастровых номеров из карточки и документов;
- скачивание и парсинг DOCX/PDF/ZIP/7Z документов;
- сохранение найденных объектов в локальную базу, чтобы повторно не искать.

### 3. Площадки торгов и агрегаторы лотов

Источники:

- `new.etpgpb.ru`;
- `sberbank-ast.ru`;
- `rts-tender.ru`;
- `fabrikant.ru`;
- региональные/отраслевые страницы, которые ссылаются на torgi.gov.ru.

Что можно получать:

- описание объекта;
- кадастровые номера;
- адреса;
- документы;
- продавца/собственника/балансодержателя;
- иногда фото объекта.

Роль в системе:

- fallback к ГИС Торги;
- часто страницы индексируются лучше, чем сам `torgi.gov.ru`;
- полезны для получения документов и подтверждения собственника.

Что нужно доработать:

- сделать общий `AuctionPageProvider`;
- поддержать несколько доменов как плагины;
- извлекать `torgi.gov.ru` notice/lot id из текста и ссылок;
- связывать с основным лотом.

### 4. Федресурс / банкротные торги

Источники:

- `fedresurs.ru`;
- `bankrot.fedresurs.ru`.

Что можно получать:

- банкротные торги;
- должника: юрлицо или физлицо;
- ИНН/ОГРН должника, если юрлицо;
- арбитражного управляющего;
- сообщения и документы;
- кадастровые номера из описаний/документов.

Роль в системе:

- источник владельца/текущего распоряжения имуществом для банкротных объектов;
- хороший путь к реальным людям: арбитражный управляющий, организатор торгов.

Что нужно доработать:

- сделать `FedresursProvider`;
- поиск по кадастровому номеру, адресу, названию объекта, ИНН;
- парсинг сообщений и документов;
- сохранять должника, управляющего, организатора.

### 5. Суды и арбитраж

Источники:

- `kad.arbitr.ru`;
- `sudact.ru`;
- карточки дел из поисковой выдачи.

Что можно получать:

- споры по объекту/кадастровому номеру;
- стороны: собственник, арендатор, банк, администрация;
- ИНН юрлиц;
- иногда договоры, аренду, обременения.

Роль в системе:

- вторичное подтверждение владельца или пользователя здания;
- полезно, если НСПД дал кадастр, но владелец не найден.

Что нужно доработать:

- сделать `LegalCaseProvider`;
- искать по кадастровому номеру и адресу;
- извлекать стороны и роли.

## Важное ограничение по владельцам

С 1 марта 2023 года персональные данные собственников-физлиц в ЕГРН закрыты для третьих лиц без согласия собственника. Поэтому бесплатный легальный путь не может стабильно выдавать ФИО физлица-собственника по кадастру.

Для юрлиц путь рабочий:

- кадастр/лот/документ дает ИНН или название собственника;
- DaData/ЕГРЮЛ подтверждает компанию;
- далее ищем гендиректора, учредителей, технических ЛПР и контакты по открытым источникам.

Для физлиц путь ограниченный:

- можно показывать `owner_type=person_hidden`;
- искать публичные следы только если ФИО прямо опубликовано в торгах/суде/Федресурсе/документах;
- нельзя выдумывать или покупать серые базы.

## Что надо изменить в архитектуре

Нужна не одна функция `resolve cadastre`, а pipeline:

1. `ObjectDiscovery`
   - карты;
   - torgi/fedresurs/auction pages;
   - локальный кэш найденных лотов.

2. `CadastreEvidence`
   - НСПД;
   - ГИС Торги;
   - документы лотов;
   - судебные документы;
   - web pages.

3. `OwnerEvidence`
   - собственник/продавец/балансодержатель из документов;
   - ИНН/ОГРН;
   - confidence и источник.

4. `CompanyResolution`
   - DaData/ЕГРЮЛ;
   - директор;
   - учредители;
   - цепочка владения.

5. `LprAndContacts`
   - директор;
   - техдиректор;
   - главный инженер;
   - главный энергетик;
   - эксплуатация объекта;
   - контакты только с URL-доказательством.

6. `Evidence UI`
   - в карточке показывать, что именно подтверждено;
   - отдельно показывать, что не подтверждено;
   - не смешивать `кадастр найден` и `владелец найден`.

## Приоритет разработки

1. Убрать hardcoded `known_public_sources.py` как основной механизм.
2. Сделать нормальный `TorgiGovProvider`.
3. Сделать индекс/кэш лотов по региону и кадастровым номерам.
4. Улучшить НСПД:
   - координаты -> ОКС;
   - адрес -> candidates;
   - участок -> связанные здания.
5. Добавить парсинг документов лотов.
6. Добавить `FedresursProvider`.
7. Добавить таблицы evidence/source.
8. Перестроить UI карточки:
   - объект;
   - кадастр;
   - владелец;
   - компания;
   - ЛПР;
   - контакты;
   - доказательства.

## Критерий готовности новой версии

Карточка считается рабочей только если:

- есть конкретный объект;
- есть фото фасада или внешний вид;
- есть кадастровый статус:
  - `matched`;
  - `not_found`;
  - `needs_manual_review`;
- если кадастр найден, есть источник и URL;
- если владелец найден, есть источник и URL;
- если ЛПР найден, есть роль и источник;
- если контакт найден, есть URL, где этот контакт опубликован;
- если чего-то нет, карточка не скрывается, но явно показывает причину.
